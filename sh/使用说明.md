# 一键发布脚本使用说明（Windows）

## 这套文件是什么

| 文件 | 作用 | 入库 | 要不要改 |
|---|---|---|---|
| `deploy.bat` | **Windows 一键发布入口**（双击即可）：mvn 打包 → 传 jar/脚本 → 远端重启 | ✅ | 只改本机构建环境那几行 |
| `server.env` | **服务器运行参数**：部署目录 / JDK 路径 / JVM 参数 / 启动参数 | ✅ | 改端口、改启动参数改这里 |
| `remote.sh` | 服务器上的执行逻辑（停旧 → 换新 jar → 启动 → 探活），由 `deploy.bat` 自动上传 | ✅ | 通常不用改 |
| `deploy.env.example` | 服务器连接信息**模板**（占位符，无真实值） | ✅ | 不用改 |
| `deploy.env` | 服务器**连接信息**：IP / 账号 / 口令 / 主机指纹 | ❌ 不入库 | 换服务器/改口令时改这里 |
| `plink.exe` / `pscp.exe` | 命令行版 SSH/SCP（支持把口令写进配置自动登录） | ❌ 不入库 | 不用改，缺失时自行下载 |

> **两个 env 文件的分工就是「密钥 / 非密钥」**：
> `deploy.env` 装 IP、账号、口令、主机指纹，永远不进版本库；
> `server.env` 装部署目录、JDK、JVM 与启动参数，进版本库，并且会被上传到服务器
> 供 `remote.sh` 读取。**每次发布两个文件都会被重新读取**，改完不用动脚本。

## 首次配置（新机器 / 新克隆下来时做一次）

1. 把 `deploy.env.example` 复制成 `deploy.env`：
   `copy deploy.env.example deploy.env`
2. 填入真实的 IP / 账号 / 口令 / 主机指纹，字段含义见模板里的注释。
3. 确认 `plink.exe` 与 `pscp.exe` 在本目录（没有就从 putty.org 下载，
   放进来即可，`deploy.bat` 会报缺少时提示）。

缺 `deploy.env` 时 `deploy.bat` 会直接停下并提示怎么补，不会带着空口令去连服务器。

## 怎么用 —— 最简单的用法

> 平时发新版，只要**双击 `deploy.bat`**，一路等它跑完即可。
> 它自动完成：`mvn clean package -DskipTests` → 传新 jar → 传 `remote.sh` / `server.env`
> → 停服务器旧进程 → 换 jar → `nohup` 启动 → 探活。

## 常用命令（在 cmd 里进到 sh 目录后执行）

```bat
deploy.bat          或  deploy.bat all     一键完整发布（构建 + 上传 + 重启）
deploy.bat deploy                        只发布不重新构建（用已有的 target\*.jar）
deploy.bat build                         只做 mvn clean package -DskipTests
deploy.bat restart                       不动 jar，只重启服务器上的服务
deploy.bat status                        查看服务器上的运行进程 + 最近日志
```

## 想改什么，改哪个文件

| 想改的东西 | 改哪 |
|---|---|
| 服务器 IP / 账号 / 口令 / 主机指纹 | `deploy.env` |
| 部署目录、远端 JDK 路径 | `server.env` 的 `REMOTE_DIR` / `JAVA` |
| 应用端口、启动参数（含各类开关） | `server.env` 的 `ARGS` |
| JVM 内存 / GC 参数 | `server.env` 的 `OPTS` |
| 本机 Maven 路径、JDK8 路径、项目目录 | `deploy.bat` 顶部「本机构建环境」那三行 |

> ⚠️ `ARGS` 里的开关一个都不能少。yml 里这些开关默认都是 `false`，
> 而配置表**不回写** `enabled`，所以线上全靠 `server.env` 的 `ARGS` 显式打开 ——
> 少一个，功能会在服务照常运行的情况下静默失效（例如少了
> `--watch.dingtalk.enabled=true`，钉钉告警 / 关键时点快报 / 用户反馈全部发不出去）。

## 发布流程细节

1. **打包**：本机用 JDK8 跑 `mvn clean package -DskipTests=true`，产物 `target\stock-kline-data-crawler.jar`。
2. **上传**：新 jar 先传成 `stock-kline-data-crawler.jar.new`（不直接覆盖，防止传到一半服务坏掉）；
   同时上传 `remote.sh` 与 `server.env`。
3. **停旧**：精确匹配并杀掉正在运行的旧 java 进程（给 4 秒宽限，没退再 `kill -9`）。
4. **换 jar**：把 `.jar.new` 改名成正式 `.jar`，之后启动的就是新版本。
5. **启动**：`setsid + nohup` 后台启动，保证关掉发布窗口进程也不死；写 PID 文件并等 8 秒探活，
   起不来会自动打印最近日志。

> 脚本在上传时会先 `tr -d '\r'` 洗掉 CR 再交给远端 bash，
> 所以本机的 `remote.sh` 即便被 Windows 工具改成 CRLF 行尾，也不影响发布。
> 仓库里另有 `.gitattributes` 把 `*.sh` 钉成 LF、`*.bat` / `*.env` 钉成 CRLF。

## 回滚

服务器部署目录里可以放 `stock-kline-data-crawler.jar.bak-<日期>` 备用 jar。
回滚 = 把某份改回正式名，再执行 `deploy.bat restart`：

```bash
cd /home/stock-backtesting
cp stock-kline-data-crawler.jar.bak-20260913_0008 stock-kline-data-crawler.jar
```

> 注意：**当前 `remote.sh` 不会自动生成备份**（`swap_jar()` 只做改名），
> 发布前若要留退路，请先手工在服务器上 `cp` 一份当前 jar 为 `.bak-日期`。

## 常见问题

- **双击后窗口一闪而过 / 报 mvn 找不到**：确认 `deploy.bat` 顶部 `MVN` 路径是本机真实路径。
- **报 `not a valid format for a manual host key specification`**：`deploy.env` 里的
  `HOSTKEY` 少字符了。SHA256 指纹固定是 `SHA256:` + 43 位 = **50 字符**，
  按 `deploy.env.example` 里的说明重新取一次，注意别漏掉中间可能出现的 `/`。
- **报 `Cannot confirm a host key`**：服务器主机指纹变了（重装/换 IP）。按上面的方法重新取指纹，
  覆盖 `deploy.env` 的 `HOSTKEY`。
- **报缺少 `deploy.env`**：还没做首次配置，见上面「首次配置」。
- **`remote.sh` 报 `set: -: invalid option`**：脚本被改成了 CRLF 行尾。用 `deploy.bat` 发布不受影响
  （上传前会洗掉 CR）；若要在服务器上手跑，先 `tr -d '\r' < remote.sh > /tmp/remote_lf.sh`。
