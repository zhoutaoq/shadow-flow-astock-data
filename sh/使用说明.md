# 一键发布脚本使用说明（Windows）

## 这套文件是什么

| 文件 | 作用 | 入库 | 要不要改 |
|---|---|---|---|
| `deploy.bat` | **Windows 一键发布入口**（双击即可）：mvn 打包 → 传 jar/脚本 → 远端重启 | ✅ | 只改本机构建环境那几行 |
| `server.env` | **服务器运行参数**：部署目录 / JDK 路径 / JVM 参数 / 启动参数 | ✅ | 改端口、改启动参数改这里 |
| `app.env` | **应用密钥**：数据库口令 / 超管初始口令 / 行情令牌 / 钉钉机器人 | ❌ 不入库 | 改凭据改这里。v1.6.4 起位置在 `shadow-flow-biz/src/main/resources/app.env`，打进 jar 随包发布 |
| `app.env.example` | 应用密钥**模板**（占位符 + 字段说明），与 `app.env` 同目录 | ✅ | 不用改 |
| `remote.sh` | 服务器上的执行逻辑（停旧 → 换新 jar → 启动 → 探活），由 `deploy.bat` 自动上传 | ✅ | 通常不用改 |
| `deploy.env.example` | 服务器连接信息**模板**（占位符，无真实值） | ✅ | 不用改 |
| `deploy.env` | 服务器**连接信息**：IP / 账号 / 口令 / 主机指纹 | ❌ 不入库 | 换服务器/改口令时改这里 |
| `plink.exe` / `pscp.exe` | 命令行版 SSH/SCP（支持把口令写进配置自动登录） | ❌ 不入库 | 不用改，缺失时自行下载 |

> **三份配置的分工就是「密钥 / 非密钥 / 机器」**：
> `deploy.env` 装 IP、账号、口令、主机指纹（本机连服务器用），永远不进版本库；
> `app.env` 装数据库口令、超管初始口令、行情令牌、钉钉机器人（服务自身要用的凭据），
> 同样不进版本库 —— 位置在 `shadow-flow-biz/src/main/resources/app.env`，打包时随 jar 走；
> `server.env` 装部署目录、JDK、JVM 与启动参数，进版本库，随每次发布上传到
> 服务器供 `remote.sh` 读取。**每次发布都会被重新读取**，改完不用动脚本。
>
> 装载方式（v1.6.4 起没有环境变量这一层）：`ShadowFlowApplication.main()` 最先调
> `AppEnv.load()` 从 classpath 读 `app.env`、把键值设成 JVM 系统属性，
> `application.yml` 里的 `${DB_PASSWORD}` / `${ADMIN_PASSWORD}` / `${SHADOWFLOW_API_TOKEN}` /
> `${DINGTALK_WEBHOOK}` 占位符就靠它取到真实值。**读不到 `app.env` 服务直接拒绝启动**；
> 值还是「在此填写…」占位文字的项按未配置处理。本地 `java -jar`、IDE 与服务器行为完全一致。
> 想核对装没装进来，看「系统配置」页右上角的**环境查看**（只读弹窗）。

## 首次配置（新机器 / 新克隆下来时做一次）

1. 把 `deploy.env.example` 复制成 `deploy.env`：
   `copy deploy.env.example deploy.env`
2. 填入真实的 IP / 账号 / 口令 / 主机指纹，字段含义见模板里的注释。
3. 把 `shadow-flow-biz/src/main/resources/app.env.example` 复制成同目录的 `app.env`：
   `cd shadow-flow-biz/src/main/resources && copy app.env.example app.env`
4. 填入真实凭据（数据库口令 / 超管初始口令 / 行情令牌 / 钉钉机器人），
   字段含义与取值来源见模板里的注释。
5. 确认 `plink.exe` 与 `pscp.exe` 在本目录（没有就从 putty.org 下载，
   放进来即可，`deploy.bat` 会报缺少时提示）。

缺 `deploy.env` 时 `deploy.bat` 会直接停下并提示怎么补，不会带着空口令去连服务器；
缺 `app.env`（jar 里没有）时服务**拒绝启动**并在 stderr 给出补齐指引 ——
这是有意的 fail-fast，别试图绕过它。

## 怎么用 —— 最简单的用法

> 平时发新版，只要**双击 `deploy.bat`**，一路等它跑完即可。
> 它自动完成：`mvn clean package -DskipTests` → 传新 jar → 传 `remote.sh` / `server.env`
> → 停服务器旧进程 → 换 jar → `nohup` 启动 → 探活。

## 常用命令（在 cmd 里进到 sh 目录后执行）

```bat
deploy.bat          或  deploy.bat all     一键完整发布（构建 + 上传 + 重启）
deploy.bat deploy                        只发布不重新构建（用已有的 target\*.jar）
deploy.bat build                         只做 mvn clean package -DskipTests
deploy.bat restart                       不动 jar，只重启服务器上的服务
deploy.bat status                        查看服务器上的运行进程 + 最近日志
```

## 想改什么，改哪个文件

| 想改的东西 | 改哪 |
|---|---|
| 数据库口令 / 超管初始口令 / 行情令牌 / 钉钉机器人 | `shadow-flow-biz/src/main/resources/app.env`（改完重新打包发布） |
| 服务器 IP / 账号 / 口令 / 主机指纹 | `deploy.env` |
| 部署目录、远端 JDK 路径 | `server.env` 的 `REMOTE_DIR` / `JAVA` |
| 应用端口、启动参数（含各类开关） | `server.env` 的 `ARGS` |
| JVM 内存 / GC 参数 | `server.env` 的 `OPTS` |
| 本机 Maven 路径、JDK8 路径、项目目录 | `deploy.bat` 顶部「本机构建环境」那三行 |

> ⚠️ `ARGS` 里的开关一个都不能少。yml 里这些开关默认都是 `false`，
> 而配置表**不回写** `enabled`，所以线上全靠 `server.env` 的 `ARGS` 显式打开 ——
> 少一个，功能会在服务照常运行的情况下静默失效（例如少了
> `--shadowflow.notify.enabled=true`，钉钉告警 / 关键时点快报 / 注册通知 / 用户反馈全部发不出去）。
>
> ⚠️ v1.6.0 把总开关由 `--watch.dingtalk.enabled` 改名为 `--shadowflow.notify.enabled`。
> 老参数已失效，带着它启动只会在日志里得到一条 WARN，通知则一条都发不出去。

## 发布流程细节

1. **打包**：本机用 JDK8 跑 `mvn clean package -DskipTests=true`，产物
   `shadow-flow-biz\target\shadow-flow-biz.jar`。
2. **上传**：新 jar 先传成 `shadow-flow-biz.jar.new`（不直接覆盖，防止传到一半服务坏掉）；
   同时上传 `remote.sh` 与 `server.env`。应用密钥在 jar 里，不用单独传。
3. **停旧**：精确匹配并杀掉正在运行的旧 java 进程（给 4 秒宽限，没退再 `kill -9`）。
4. **换 jar**：把 `.jar.new` 改名成正式 `.jar`，之后启动的就是新版本。
5. **启动**：`setsid + nohup` 后台启动，保证关掉发布窗口进程也不死；写 PID 文件并等 8 秒探活，
   起不来会自动打印最近日志。

> ⚠️ **v1.6.0 换包名的一次性动作**：进程匹配与清理都按 `server.env` 的 `JAR_NAME` 走，
> 换名后 `swap_jar()` 扫不到旧的 `stock-kline-data-crawler.jar`，也**停不掉正在运行的老进程**。
> 首次发布前先手工执行一次：
>
> ```bash
> cd /home/stock-backtesting
> pkill -f '[s]tock-kline-data-crawler.jar'      # 括号是为了别把这条命令自己匹配进去
> rm -f stock-kline-data-crawler.jar stock-kline-data-crawler.jar.bak
> ```

> 脚本在上传时会先 `tr -d '\r'` 洗掉 CR 再交给远端 bash，
> 所以本机的 `remote.sh` 即便被 Windows 工具改成 CRLF 行尾，也不影响发布。
> 仓库里另有 `.gitattributes` 把 `*.sh` 钉成 LF、`*.bat` / `*.env` 钉成 CRLF。

## GitHub Actions 自动发布（推送到 GitHub 即发布）

`.github/workflows/deploy.yml`：推送到 `github` / `main` 分支（或在 Actions 页面手动 Run workflow）
就自动跑完和 `deploy.bat` 一样的流程 —— 远端那段命令串与 `deploy.bat` **逐字相同**，
部署目录 / jar 名 / 端口仍旧从 `server.env` 读，不在 CI 里另存一份配置。

| 环节 | 做什么 |
|---|---|
| 打包 | GitHub runner 上 Temurin JDK 8 + `mvn -B clean package -DskipTests` |
| 密钥 | 从仓库 Secret `APP_ENV` 写回 `shadow-flow-biz/src/main/resources/app.env` 后再打包（缺了服务拒绝启动） |
| 上传 | `sshpass + scp`：jar 先传成 `.jar.new`，再传 `remote.sh` / `server.env` |
| 重启 | 跑 `remote.sh restart`（停旧 → 换 jar → `setsid` 启动） |
| 探活 | 轮询 `http://<SSH_HOST>:<ARGS 里的 server.port>/`，最多 24 次 × 5s |

需要的仓库 Secrets（Settings → Secrets and variables → Actions）：

| Secret | 值 |
|---|---|
| `SSH_HOST` | 服务器 IP |
| `SSH_USER` | 登录账号 |
| `SSH_PASSWORD` | 登录口令（与 `deploy.env` 的 `PWD` 同一份） |
| `SSH_KNOWN_HOSTS` | 服务器主机公钥，取法 `ssh-keyscan -t ed25519 <IP>`（输出整行粘进去） |
| `APP_ENV` | `shadow-flow-biz/src/main/resources/app.env` 全文（不入库，打进 jar） |
| `SSH_PORT` | 可选，不给默认 22 |

> ⚠️ 改了 `app.env` 里的凭据（行情令牌 / 钉钉机器人 / 各种口令）要**同步更新 Secret `APP_ENV`**，
> 否则 CI 打出来的包还是旧凭据。改 `server.env`（端口、JVM 参数、启动开关）不用动任何 Secret。

## 回滚

服务器部署目录里会保留「当前包 + 上一版」两份（`shadow-flow-biz.jar` 与
`shadow-flow-biz.jar.bak`）。回滚 = 把备份改回正式名，再执行 `deploy.bat restart`：

```bash
cd /home/stock-backtesting
cp shadow-flow-biz.jar.bak shadow-flow-biz.jar
```

> `remote.sh` 的 `swap_jar()` 每次发布都会把在跑的包滚成 `.bak`，所以上一版随时可取；
> 更早的版本会被自动清掉，只留最近一份。

## 常见问题

- **双击后窗口一闪而过 / 报 mvn 找不到**：确认 `deploy.bat` 顶部 `MVN` 路径是本机真实路径。
- **报 `not a valid format for a manual host key specification`**：`deploy.env` 里的
  `HOSTKEY` 少字符了。SHA256 指纹固定是 `SHA256:` + 43 位 = **50 字符**，
  按 `deploy.env.example` 里的说明重新取一次，注意别漏掉中间可能出现的 `/`。
- **报 `Cannot confirm a host key`**：服务器主机指纹变了（重装/换 IP）。按上面的方法重新取指纹，
  覆盖 `deploy.env` 的 `HOSTKEY`。
- **报缺少 `deploy.env`**：还没做首次配置，见上面「首次配置」。
- **`remote.sh` 报 `set: -: invalid option`**：脚本被改成了 CRLF 行尾。用 `deploy.bat` 发布不受影响
  （上传前会洗掉 CR）；若要在服务器上手跑，先 `tr -d '\r' < remote.sh > /tmp/remote_lf.sh`。
