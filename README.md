# 金牛数据（stock-kline-data-crawler）

股票日K线数据管理与策略回测系统。数据来自「歪枣网（waizao）」行情供应商，落库到本地 MySQL，
基于原生 HTML + ECharts 提供数据更新、K线分析与策略回测；
另有一块独立的**实时盯盘提醒**：行情取新浪财经，超阈值或封板 / 开板时推钉钉群机器人。

技术栈：Spring Boot 2.7.6 + JdbcTemplate + MySQL 8 + 原生 JS（ECharts）。

## 一、启动的必须条件

### 1. 环境依赖

| 依赖 | 版本要求 | 说明 |
|---|---|---|
| JDK | **8**（`pom.xml` 中 `java.version=1.8`） | Spring Boot 2.7.x 项目，建议用 64 位 JDK 8 |
| Maven | 3.6+ | 本机固定用 `C:\workspace\java\apache-maven-3.8.1\bin\mvn.cmd` |
| MySQL | **8.0** | 需要能连通的实例与一个空库（默认库名 `mydb`） |
| 网络 | 可访问 `api.waizaowang.com` | 只有「数据更新 / 回测补数据」需要，纯查库与回测不需要 |

### 2. 准备数据库

应用启动时会**自动建表**（`spring.sql.init.mode=always`，执行 `src/main/resources/schema.sql`，
全部是 `CREATE TABLE IF NOT EXISTS`），但**数据库本身要你自己先建**：

```sql
CREATE DATABASE IF NOT EXISTS mydb DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
```

连接信息在 `src/main/resources/application.yml`：

```yaml
spring:
  datasource:
    url: jdbc:mysql://127.0.0.1:3306/mydb?...
    username: root
    password: ${DB_PASSWORD:root123456}   # 建议用环境变量覆盖，别把口令写死
```

正式环境用环境变量注入，不要依赖默认值：

```bash
export DB_PASSWORD=你的真实口令
```

### 3. 配置 waizao 的 token（数据更新的前提）

token 是供应商凭据，**运行期可改，存在配置表里、并按用户隔离**，不要求写死在配置文件：

- **推荐做法**：登录后打开「系统 → 实时通知配置」页（`/pages/config.html`），
  在「我的数据接口令牌」里粘贴令牌保存，立即生效、不用重启。
- **令牌挂在账号名下**：抓数时用「发起这一请求的人」自己的令牌；该用户没配过则回落到
  **系统级令牌**（`waizao_sys_config` 里 `场景 = waizao`、`键 = token`、`归属用户 = 0` 那一行）。
  盯盘等后台任务没有登录态，用的就是系统级那一份。
- **`application.yml` 里的 `waizao.api.token` 只在系统级配置为空、首次启动时作为种子写入一次**，
  之后一律以配置表为准。
- 首次启动如果没配 token，日志会打印 `⚠️ 系统级 waizao/token 为空`，此时还没配自己令牌的用户
  抓取都会失败。

总开关 `waizao.api.enabled`（默认 `true`）：置为 `false` 时，请求在发出前就被拦住，
不会消耗调用次数（供应商接口按次计费，停用必须真拦住）。

### 4. 端口与一个容易踩的坑

默认端口 **8081**（`server.port: 8081`），启动后访问 <http://127.0.0.1:8081/>。

⚠️ 如果环境变量里存在 **`SERVER__PORT`**（本机被其他程序占用了 53282），
Spring Boot 的宽松绑定会把它解析成 `server.port`，**覆盖掉配置文件里的 8081**，
表现为启动时报端口被占用。启动时显式指定端口即可：

```bash
mvn spring-boot:run -Dspring-boot.run.arguments=--server.port=8081
# 或跑 jar 时
java -jar target/stock-kline-data-crawler.jar --server.port=8081
```

### 5. 启动

```bash
# 开发启动
mvn spring-boot:run

# 或打包后运行
mvn clean package -DskipTests
java -jar target/stock-kline-data-crawler.jar
```

Windows（PowerShell）本机示例：

```powershell
$env:JAVA_HOME = "C:\workspace\java\jdk8x64"
& "C:\workspace\java\apache-maven-3.8.1\bin\mvn.cmd" spring-boot:run
```

### 6. 首次启动后建议做的一件事：导入股票列表

股票列表源头是 `resources/stock-list.json`，导入后才能在页面上点选股票。

- 接口：`POST /api/stocks/import`
- 或在「分析回测 → 股票列表」页操作

```bash
curl -X POST http://127.0.0.1:8081/api/stocks/import
```

## 二、运行模式：数据库模式 / 无数据库模式

`application.yml` 里的 `waizao.db.enabled` 决定跑哪种模式：

| `waizao.db.enabled` | 模式 | 数据从哪来 | 结果存哪 | 可用功能 |
|---|---|---|---|---|
| `false`（**默认**） | 无数据库模式 | 每次向供应商现取 | 不存，只在页面展示 | 股票列表（只读）、股票K线、策略回测 |
| `true` | 数据库模式 | 本地 MySQL 日K表 | 落库，可回看历史 | 全部功能 |

### 无数据库模式

- **不需要 MySQL，也不用建库**：启动阶段压根不连数据库（数据源自动配置已排除）。
- **令牌由服务端按用户维护，开箱即用**：系统级默认令牌（= `waizao.api.token`）在首次启动时
  播种进配置，匿名请求（首页、K线查看）直接用它，不再弹填写框、也不往浏览器存令牌。
  登录后到「实时通知配置」页可配置**自己专属的令牌**，只对自己的请求生效；
  换浏览器 / 换机器登录同一账号，用的还是同一份。
- **选股**：候选读本地 `resources/stock-list.json`，**只收沪深A股**（6 位数字且
  60 / 68 / 00 / 30 开头，港股、基金债券、北交所在载入阶段就丢掉）；名录里没有的标的，
  直接敲完整代码（5~6 位数字）回车即可，不必先从列表里点选。
  匹配在**服务端**做，前端不下载名录，输入后按 200ms 防抖调接口取候选。
- **一套前端页面**：两种模式共用 `pages/*.html`，页面按 `/api/mode` 返回的
  `dbEnabled` 自行裁剪（隐藏写操作入口、隐藏依赖库表的区块），没有 `pages/nodb/` 第二套页面。
- **菜单按模式裁剪**：无数据库模式下只生成不依赖库表的入口 ——
  **概览 → 分析回测（股票列表 / K线分析 / 策略回测）→ 实时通知配置**；
  「数据更新」整组和「调用日志」「接口调试」连菜单项都不生成，用到库表的 Controller 启动时也不注册。
- **股票K线现取**：`/pages/chart.html` 在无数据库模式下由用户直接给起止日期，一次取回
  （自然日跨度不超过 `waizao.max-span-days`）；数据库模式下默认近三个月，拖拽到边缘再懒加载。
- **所有明细表格收进弹窗**：K线页「当前视窗明细」、回测页「每日账户 / 买卖明细」
  都不再平铺，统一收成 K 线图上方的按钮，点击弹出 900px 弹窗**分页**展示。
- **单次跨度上限**：任何一次取数的自然日跨度不能超过 `waizao.max-span-days`（默认 **1200** 天），
  超了在发请求之前就被拦住 —— 数据要现取，跨度越大一次请求越重（K线页按 365 天一批，天然在上限内）。
- **回测不落盘**：照常跑、照常出结果（K线买卖点 / 盈亏曲线 / 明细都在），
  但不写任何表，刷新后不可回看，「历史回测」整块隐藏。

### 切回数据库模式

```yaml
waizao:
  db:
    enabled: true
```

改完重启，按「一、启动的必须条件」准备 MySQL 即可。

### 策略回测

回测必须指定**一只股票 + 起止时间**。数据库模式下结果落库、可回看；
无数据库模式下照常出结果但不留存，且起止日期的自然日跨度受 `waizao.max-span-days` 限制。

**回测配置**：一行四个卡片 —— ①回测对象（股票、账户起始金额、手续费滑点）
②时间范围（起止日期 + 快捷区间，实时显示跨度）③买入策略 ④卖出策略

- 账户起始金额
- 手续费滑点：单一摩擦成本费率，页面按 % 录入（默认 0.01%，即万分之一），买入按成交额加价、卖出减价，各计一次

**买卖策略**（组件化，买入和卖出各配一组，组内支持「或 / 且」组合）

| 组件 | 含义 |
|---|---|
| 近N日涨幅 | 近 n 个交易日涨幅 > / < x（x 可为负） |
| 连续N日站上/跌破均线 | 连续 n 个交易日收盘价都 > / < m 日线 |
| 收盘价与均线 | 收盘价 > / < n 日线 |
| 成交量倍数 | 成交量 > / < 前 n 日平均成交量 × 倍数（「前 n 日」不含当日） |

**交易口径**

- 第一版为**全仓买卖**：买入按可用现金买满，卖出一次清仓
- 最小成交单位 **100 股**
- 信号在**当日收盘确认并按当日收盘价成交**；若当日封在涨跌停板上，按下节「涨跌停成交策略」处理
- 回测区间之前的数据只用于计算均线/涨幅（指标预热），不产生买卖信号
- 起止两天数据缺失时，会**自动从供应商补拉缺失的那一天**；补完仍缺才报错（如非交易日）

**涨跌停成交策略**（在「①回测对象」卡片底部选，每次回测独立生效，可随配置一起导入导出）

信号日 T 的收盘价如果封在涨跌停板上，实际不保证能成交（涨停没人卖、跌停没人买）。这一项决定怎么处置：

| 策略 | 行为 |
|---|---|
| 1 无视 | 仍按 T 日收盘价成交（保持原有行为） |
| 2 次日开盘非涨跌停立即成交 | 推到 T+1，按 T+1 开盘价成交 |
| 3 次日非涨跌停且涨跌幅达 n% | 推到 T+1，除上面条件外，还要求相对 **T 日收盘价** 的涨跌幅满足阈值（方向可选「涨幅 > n%」或「跌幅 > n%」，页面按 % 录入） |

- 封板判定：**收盘价 == 当日最高价 且 涨幅 > 阈值** 算涨停；**收盘价 == 当日最低价 且 跌幅 < -阈值** 算跌停。
- 阈值按板块，各留 0.5% 容错：主板 9.5%、创业板 30x 与科创板 688 为 19.5%、名称含 ST 为 4.5%。
- 方向是对应的：**买入只看涨停、卖出只看跌停**（买入遇跌停、卖出遇涨停并不阻碍成交）。
- **T+1 仍然不能成交就作废**，不顺延到 T+2：买入遇 T+1 涨停开盘、卖出遇 T+1 跌停开盘，即放弃本次信号。
- 推到次日成交的那一天不再产生新信号（A股 T+1，也避免同一天既买又卖）。

**结果展示**：阶段K线带 B/S 买卖点、盈亏金额与比例双轴曲线、每日账户明细、交易明细；
配置支持 JSON 导入导出。

## 五、实时盯盘提醒

独立于其它功能的一块：行情取自**新浪财经**，不连数据库、不走 waizao 供应商、不落任何表，
只在内存里留「上一次的价格」做比对 —— 价格偏离超阈值、或**封板 / 开板**时推钉钉群机器人。

### 1. 配置（`application.yml` 的 `watch` 段）

| 配置项 | 默认 | 说明 |
|---|---|---|
| `watch.enabled` | `true` | 总开关，关掉后所有 bean 不创建、调度不注册 |
| `watch.watch-list-file` | `resources/watch-list.txt` | 盯盘名单，每行一个股票名称 |
| `watch.stock-list-file` | `resources/stock-list.json` | 名称 → 代码 的索引来源 |
| `watch.interval-seconds` | `30` | 轮询间隔（秒），用 fixedDelay，上一轮跑完才计时 |
| `watch.threshold-percent` | `1.0` | 阈值（%）：与**上一次查询价格**相比的偏离绝对值 |
| `watch.thread-pool-size` | `8` | 并发查行情的线程数 |
| `watch.sina.*` | `http://hq.sinajs.cn` | 新浪行情地址与超时 |
| `watch.dingtalk.webhook` | 空 | 机器人 Webhook（含 `access_token`）；**留空则不推送，只打日志** |
| `watch.dingtalk.secret` | 空 | 机器人安全设置里的「加签」密钥；留空表示不加签 |

### 2. 盯盘名单

`resources/watch-list.txt` 每行一个，**改完不用重启**（每轮轮询重读）：

```text
# 以 # 开头是注释，空行忽略
平安银行              # 按名称识别代码（查 stock-list.json）
600519                # 直接写 6 位代码
600519 贵州茅台       # 代码 + 名称（空格 / 逗号 / 顿号都认）
```

只处理沪深A股（60/68/00/30 开头）。名称识别不到会打 warn 日志并跳过该行。

### 3. 执行流程

定时调度（`watch.interval-seconds`）→ 线程池并发向新浪拉现价
（`GET {sina.base-url}/list=sh600000`，带 `Referer: https://finance.sina.com.cn`，响应 GBK）
→ 与内存中该代码上一次的价格比对 → 偏离 ≥ 阈值则推钉钉。

- **首轮只建基线、不推送**（没有"上一次"可比），进程重启同理。
- 停牌 / 未开盘时新浪现价为 0，该轮跳过、基线不更新，恢复后仍与停牌前的价格比。
- 推送失败或未配 webhook 时，消息内容会原样打进日志，不丢信息。
- **非交易时段（非周一至周五、或不在 9:30-11:30 / 13:00-15:00）不调接口**。
  例外：某只票还没有基线时仍会调一次，否则永远建不出基线（中途加进名单的新票同理）。
- 每次调用行情接口都会记日志：成功 `info`（现价 / 涨跌幅 / 行情时间 / 耗时），失败与"无有效数据" `warn`。

### 4. 涨跌停通知

在盯盘名单范围内（不额外扫全市场，也不调其它接口），用同一次行情返回的
**现价、当日最高价、最低价、昨收**判断是否封板：

| 判定 | 条件 |
|---|---|
| 涨停 | 现价 == 当日最高价 **且** 涨幅 > 阈值 |
| 跌停 | 现价 == 当日最低价 **且** 跌幅 < -阈值 |

阈值按板块给，各留 0.5% 容错：**主板 9.5%**、**创业板 30x 与科创板 688 为 19.5%**、**名称含 ST 为 4.5%**。

推送时机：**封板状态发生变化**时才推（首轮只建基线不推）：

| 上一轮 | 这一轮 | 推送 |
|---|---|---|
| 未封板 | 涨停 / 跌停 | `xx 涨停` / `xx 跌停` |
| 涨停 | 不再是涨停 | `xx 打开涨停` |
| 跌停 | 不再是跌停 | `xx 打开跌停` |
| 涨停 | 涨停 | 不推（连续封着不刷屏） |
| 未封板 | 未封板 | 不推 |

天地板这种极端跳变（涨停直接砸到跌停）会连推两条：先「打开涨停」再「跌停」。

```
平安银行 涨停，现价 11.72 元，涨跌幅为 10.02%。
贵州茅台 跌停，现价 1500.00 元，涨跌幅为 -10.00%。
平安银行 打开涨停，现价 11.50 元，涨跌幅为 8.10%。
```

### 5. 消息格式（超阈值）

```
平安银行 在近 30 s 内涨幅达到 1.24%，现价 11.72 元，涨跌幅为 0.17%。
```

「近 x s」是本次与上次成功查询的时间差；「涨跌幅」是相对昨收的当日涨跌幅。

## 六、主要接口

| 接口 | 说明 |
|---|---|
| `GET /api/mode` | 当前运行模式（是否连库、跨度上限、回测是否落盘），前端据此渲染菜单 |
| `GET /api/dir/stocks` | 股票名录联想，两种模式都在（库表 / 本地 JSON） |
| `GET /api/kline/chart`、`/api/kline/span` | K线只读取数与日期跨度，两种模式都在 |
| `GET /api/stocks`、`POST /api/stocks/import` | 股票列表查询 / 从 JSON 导入（数据库模式） |
| `GET /api/klines`、`/span`、`/chart`、`/coverage` | 日K线 CRUD、日期跨度、K线图数据、数据覆盖统计 |
| `POST /api/fetch`、`/api/fetch/jobs` | 数据更新（支持预览模式）与批处理任务 |
| `POST /api/backtest/run`、`GET /api/backtest`、`GET /api/backtest/{id}`、`GET /api/backtest/progress/{taskId}` | 回测执行、历史列表、回看、执行进度 |
| `GET/POST /api/sys-config` | 我名下的配置项（按登录用户隔离，需登录） |
| `GET /api/call-logs` | 调用日志查询 |
| `GET /api/dashboard` | 概览数据 |

## 七、注意事项

- **供应商接口按次计费**：批量更新超过阈值会弹二次确认；预览模式同样消耗调用次数。
- 回测时若触发自动补数据，也会产生真实调用（每次回测最多补 2 天）。
- 接口调试页只渲染结果，**不做落盘**，可放心用来验证参数。
- 表结构变更：直接改 `schema.sql`（`CREATE TABLE IF NOT EXISTS`，重启生效），
  已有表加列需自行写 `ALTER`。
- **钉钉机器人收不到消息**，先去群里看机器人的「安全设置」：设了「自定义关键词」就要求消息正文
  必须包含该关键词，否则钉钉返回 `errcode: 310000 关键词不匹配`（消息其实已经发出去了，是被服务端拒收）。
  解决：把关键词加进盯盘名单的股票名里，或改用「加签」并配上 `watch.dingtalk.secret`。
- **盯盘的涨跌停阈值是写死的常量**（主板 9.5% / 创业科创 19.5% / ST 4.5%），
  没有放进 `application.yml`；要改请直接改 `PriceWatchTask` 里的 `TH_*`。
