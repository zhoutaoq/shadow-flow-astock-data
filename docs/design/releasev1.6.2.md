### 一、菜单名称与顺序可配置

配置收在「系统配置 → 外观与导航」，以「按钮 + 弹窗」提供，**默认值就是当前页面上跑的
那一套**（第一次打开弹窗看到的就是现状，不动它保存也等于没变）。

**只有「名称」与「顺序」可配，地址与权限不给配** —— 这是刻意的边界：

| 可配 | 不可配（留在代码里） | 理由 |
|---|---|---|
| 名称（≤ 12 字） | `href` 地址 | 地址可配 = 能配出一个点进去 404 的死菜单 |
| 顺序（上移 / 下移） | `login` 登录要求 | 权限是约束而不是展示偏好 |
| | `admin` 超管可见 | 可配 = 开一个越权入口 |

**唯一真相源**是代码里的 `MenuConfigService.BUILT_IN` 与前端 `js/common.js` 的 `NAV_ITEMS`
（两边一一对应，加菜单要同时改）。服务端只下发 `key + 名称 + 顺序`，前端按 `key` 回索引内置项 ——
所以：

- 配置里出现内置没有的 `key` 一律忽略（不会因为配置写错就多出个菜单）；
- 内置有而配置漏掉的 `key`，按内置顺序补到队尾 —— 以后往 `BUILT_IN` 加新菜单，
  老配置不会把它挤没。

**存储形态**：每个菜单项一行配置（场景 `menu`、`ownerId = 0` 系统级），
顺序单独一行 `order`（key 的逗号列表）+ 每项一行 `label.<key>`。
保存时**整份先清后写**，避免「改名 → 又改回原名」留下一条永远覆盖内置值的旧行。
`reset` 直接删光本场景行，回到内置值。

| 接口 | 说明 |
|---|---|
| `GET /api/menu` | **免登录**。全站每个页面（含首页、股票列表这些匿名入口）都要用它渲染导航；只回名称 / 顺序 / 地址，不含任何账号数据 |
| `POST /api/admin/menu` | 超管。保存并立即生效 |
| `POST /api/admin/menu/reset` | 超管。恢复默认 |

导航与首页「功能入口」共用同一份 `menuItems()`：一个菜单改名，顶栏与首页入口**一起变**，
不会出现两处叫法不一致。名称来自用户输入，`navLink()` 里对名称与地址都做了转义 ——
否则一个 `<` 就能把导航拆了。

### 二、系统 logo

先在仓库放一张出厂图 `static/img/logo.jpg`（由 `docs/design/logo.jpg` 拷入，随包发布），
超管可在「系统配置 → 外观与导航」上传替换。

**两份 logo 的关系**：

```
出厂 logo     classpath:/static/img/logo.jpg      随包发布，永远在
自定义 logo   <data-dir>/logo/logo.<ext>          上传的那份，改完立刻生效、不用重新打包
```

读取时自定义优先。之所以不往 `static/` 里写：那是打包进 jar 的资源，运行期根本改不动；
而无数据库模式下 `data/` 本来就是本服务唯一可写的运行期目录。

| 接口 | 说明 |
|---|---|
| `GET /api/logo` | **免登录**。回 `{url, customized}` |
| `GET /api/logo/view` | **免登录**。把自定义图读出来（`<img>` 请求不带自定义头，拦在登录后图就加载不出来） |
| `POST /api/admin/logo/upload` | 超管。`multipart`，落盘前校验 |
| `POST /api/admin/logo/reset` | 超管。删掉自定义那份，回到出厂图 |

- **校验**：JPG / PNG / WEBP / GIF，单张 ≤ 2MB。先写 `.tmp` 再原子改名，避免读到半张图；
  换扩展名（jpg → png）时先清掉旧图，否则按固定顺序查找会取到老的那张。
- **不做图形处理**：原样落盘。重编码（缩放 / 转格式）只会引入「传上去糊了」这类说不清的问题。
- **缓存**：URL 带 `?v=<最后修改时间>`，换图后浏览器立刻拉新图，不吃 7 天静态缓存。
- **multipart 上限**：`application.yml` 放到 4MB / 8MB。默认 1MB 会在 Spring 容器层
  先把 1–2MB 的图拒掉、报框架英文错，跟站内统一的中文提示口吻对不上；真正的 2MB 校验留在 `LogoService`。
- 顶栏品牌位、登录弹窗标题、首页品牌带大标题共用同一张图和同一个名字，
  改一处全站同步；logo 加载失败自动退回纯文字。

### 三、「用户反馈」→「问题反馈」+ 输入框放大

| 位置 | 改动 |
|---|---|
| 导航 / 首页功能入口 | 「用户反馈」→「问题反馈」（`NAV_ITEMS` + `BUILT_IN`） |
| `pages/feedback.html` | `<title>`、页内 `<h2>`（两处，含关闭态面板） |
| 钉钉消息首行 | `[关键词] 用户反馈` → `[关键词] 问题反馈`（机器人「自定义关键词」模式靠它命中） |
| 系统配置页文案 | 第三方对接说明里的括号列举 |
| 输入框 | `min-height` 170px → **300px**，字号提到 `--fs-16`，内边距加大 |
| 反馈面板 | `max-width` 880px → **1080px**（宽屏下 880px 两侧留白过多，输入区被压得偏窄） |

### 五、留待确认

- **线上菜单配置与 logo 都还没配**，首次打开「外观与导航」看到的会是内置值（与当前页面一致）；
  上传的 logo 落 `data/logo/`，**不入发布包**，重新发布不会覆盖（除非手工清 `data/`）。

  与前端 `input[maxlength]` 两处。

  保证不糊成黑斑；若后续设计出浅色底的图，可直接替换 `static/img/logo.jpg`。
