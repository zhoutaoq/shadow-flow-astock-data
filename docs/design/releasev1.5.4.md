### 实现说明

#### 一、四个平台的实测结论

需求里点名了四家，逐家实测后**只有三家能真的接进来**，通达信整体不接入：

| 平台 | 热门股 | 板块涨跌幅 | 依据 |
|---|---|---|---|
| 东方财富 | ✅ 换手率榜 | ✅ 行业板块 | `push2…/api/qt/clist/get`（`fltt=2`，`f8`/`f3` 排序） |
| 新浪财经 | ✅ 成交额榜 | ✅ 行业板块 | `Market_Center.getHQNodeData`（`sort=amount`）、`newSinaHy.php` |
| 同花顺 | ✅ 热榜 | ❌ 不提供 | 热榜可用；板块只有 `v1/plate` 与 `thshy/…/ajax/1/`，前者固定回 `Param Error.`，后者 401 + `hexin-v` 反爬 |
| 通达信 | ❌ 未接入 | ❌ 未接入 | 没有可服务的公开行情接口，全部走带签名的私有通道 |

**同花顺没有板块、通达信整家没有，页面上如实标注「不提供」/「未接入」，
不拿别家数据顶替。** 后端的 `BoardProvider` 用两个能力位（`supportsHotStocks` /
`supportsSectors`）表达这件事，`BoardService` 只返回声明支持该能力的平台，
前端因此不会出现一张永远空着的卡片。

#### 二、开发中撞到并修掉的三件事

**1. 东财人气榜接口已失效（本地自测才发现）**

原方案热门股走东财自己的**人气榜**（`emappdata.eastmoney.com/stockrank/getAllCurrentList`，
POST + JSON 体）。实测该端点固定返回：

```json
{"globalId":"","message":"服务异常","status":-1,"code":-2,"data":null,"stack":null}
```

排查过的变体（全部同样报错）：GET / POST 各一次、加 `Content-Type: application/json;charset=UTF-8`、
补 `Origin` 与 `Referer`（`vipmoney` / `guba` / `quote` 三个域）、换浏览器 UA、
参数改成查询串、把 `globalId` 补成完整 UUID、换同域的 `getCurrentList`；
另一个人气榜通道 `gbapi.eastmoney.com/rank/stock/popularity` 直接连不通（0 字节）。

改法：热门股改用东财自己的**换手率榜**（`fid=f8`，取样范围就是沪深A股全集
`fs=m:0+t:6,m:0+t:80,m:1+t:2,m:1+t:23`）。换手率高 = 当日资金参与度高，
是「热门」的一个真实口径，且与新浪的成交额榜不重复。
**卡片如实标成「换手率榜」，不冒称人气榜。**

**2. 新浪热门股在集合竞价阶段返回 0 行**

`sort=amount&asc=0` 按成交额降序，但 09:24（尚未开盘）所有标的成交额都是 0，
排序退化成随机，前 20 条恰好全是北交所 `bj92xxxx`；代码里有个 A 股过滤
（`AShareCodes`，只收 60/68/00/30），过滤完一条不剩 → 页面一张空表。

改法：按 `limit × 5`（上限 100）多取几行再过滤，取前 `limit` 条 A 股。
因为 A 股成交额远大于北交所，多取不影响榜单名次；开盘后取到的就是真实的前 N 名。

**3. 同花顺热度值整列是空的**

`rise_and_fall`（涨跌幅）是数字节点，但 `rate`（热度）实测是**字符串**
（`"594582.0"`）。原来的工具方法只认 `isNumber()`，于是热度列全是 `-`。
改法：`emNumber` 同时接受数字与文本数字。

#### 三、与既有页面同一套约定

实时资讯页每 3 秒轮询免费公开接口，场景与首页那几个指数完全一样，
所以直接沿用已经跑通的四条：

- **后端缓存 2 秒**（略短于页面 3 秒间隔）：多人同时看 / 多开标签页时，
  并发被压成每 2 秒最多一次上游请求；
- **失败日志按分钟节流**：上游不通时若每轮都打，一天能把 `app.log` 刷爆；
- **有旧值就沿用旧值**：一次抖动不该让页面从有数变成空白，
  只有从来没取到过才把失败原因透给前端；
- **东财宿主按序回退**（`push2` → `push2delay`）：v1.5.3 已经证明主干域名在
  部分机房出口会被拒，两个都留着按序试。

在此基础上多加了三条：

- **各平台并发取数**：三家串行时整轮耗时是各家之和，页面 3 秒的节奏会被拖垮；
  并发后整轮约等于最慢那一家，单平台 4 秒超时不影响另外两家；
- **`SimpleHttp` 统一处理编码**：东财 / 新浪 json / 同花顺都是 UTF-8，新浪
  `hq.sinajs.cn` 那类老接口是 GBK，靠响应头 charset → 是否含 `\uFFFD` 自动判定；
- **前端行原地更新**：3 秒一次的重绘若把 `tbody` 掀了重建，鼠标悬停会被打断、
  滚动位置会被顶回顶部。按 `code` 认行，只改内容真的变了的格子，并给一次
  轻量高亮（`flash`）让「刚刚跳了」看得见。

前端另外用「跑完再排下一次」的 `setTimeout` 链而不是 `setInterval` ——
上游偶尔卡过 3 秒时，`setInterval` 会把请求叠起来发、越堵越多；
页面不可见（切走标签页）时停掉轮询，切回来立刻补一次。

#### 四、自测结论（本地）

- `mvn clean package -DskipTests`：BUILD SUCCESS；
- `node scripts/check_inline_js.js src/main/resources/static`：全部内联 JS 语法通过；
- 三个接口对真实上游取数：热门股 3 家各 20 条、板块 2 家各 20 条，中文无乱码，
  名次连续，涨跌幅有值（新浪板块在 09:24 前全为 0 是上游尚未计算，
  09:30 开盘后即出现真实涨跌幅与领涨股）；
- 页面用 jsdom 真实执行脚本跑了三轮 3 秒轮询，40 项断言全绿：
  卡片数（热门 3 / 板块 2）、三家表头（换手率 / 成交额 / 热度+题材）、
  行数、两位小数、涨红跌绿、工具条状态、**行 DOM 原地复用**、
  单平台失败态不影响其它卡片、无未捕获脚本错误。

> 本页匿名可用（未登记在 `AuthWebConfig.PROTECTED`），与首页 / K线查看一致 ——
> 资讯是公开行情，这几家上游本身也不需要令牌。
