## 1. 现状与痛点清单

「添加操作记录」弹窗（account.html:856-927）字段顺序：**标的 → 方向 → 数量 → 成交价 → 日期 → 「当天」勾选框**。标的输入用全站统一选择器（stock-picker.js）。逐条痛点：

| # | 痛点 | 源码证据 |
|---|---|---|
| P1 | **方向放在标的之后，切方向清空已选**：买入走全量名录、卖出只走持仓，候选集由方向决定；用户先选了标的再切「卖出」，已选被无条件清空重搜，白选一遍 | account.html:923-928（`setItems([])` + `refresh('')`） |
| P2 | **「当天」勾选框与日期字段暗藏耦合，前端不做任何处理**：日期选过去（补录）时勾选框仍亮着可勾，但后端 `sameDay = todayFlag && onToday` 会把标记吞掉——用户勾了却不见「当天」tag，无提示 | 写侧 AccountService.java:543-545；前端 account.html:876-877（勾选框常显）、:1012（无条件提交） |
| P3 | **「当天买入 / 卖出当天买入的持仓」文案是会计口径词汇**，新用户读不懂它决定什么（当日盈亏的基准价：当日买入均价 vs 昨收，AccountService.java:508-517） | account.html:921（`recTodayText`） |
| P4 | **买入没有现金上限与成交额反馈**：填数量/价格时不实时算成交额、不对照可用现金，超现金要到保存后被后端拒绝 | AccountService 现金校验在后端；前端 account.html:978-1002 只校验数量/价格正数 |
| P5 | **成交价预填是静默异步**：选完标的拉 `/api/account/price`，无 loading、失败静默；买入价格必填（AccountService.java:595），但前端不标必填、不预校验，报错兜圈子 | account.html:1034-1047 |
| P6 | **买入时无持仓上下文**：对已持仓标的加仓，看不到当前持仓量/成本价，加仓后成本被加权平均摊薄（AccountService.java:638-641）用户无感知；卖出侧有「可用 N 股」提示（account.html:936-953），买入侧没有对称信息 | account.html:941（`recAction === 'sell'` 才找持仓） |
| P7 | **选择器手输回车「没反应」**：DB 模式名录没返回该代码时，敲 `600519` 回车什么都不发生（手输兜底只认 noDb 模式的 5-6 位纯数字）；且「可直接输入完整代码后回车」的提示只在 allowManual 时出现，DB 模式用户不知道为什么被拒 | stock-picker.js:462-474（tryManual）、:159-160（提示语） |
| P8 | **首轮聚焦下拉只有一行「代码或名称」**：空关键字不拉候选（省请求），用户点开看到的是占位提示而不是可点的东西 | stock-picker.js:351-355 |
| P9 | 保存按钮无 loading 态、弹窗无字段分组，6 个字段一竖排平铺，视觉重量平均、没有主次 | account.html:862-882 |

## 2. 交互改版方案

### 2.1 P0 — 交互顺（本方案核心）

**① 方向提到第一位，切方向不清空已选**

- 字段顺序改为：**方向 → 标的 → 数量 → 成交价 → 日期**；默认「买入」。
- 切到「卖出」时：若已选标的恰在持仓里，**保留选中**，只刷新候选清单与数量上限；不在持仓里才清空并给提示（现逻辑是无差别清空，account.html:926）。
- 卖出且持仓为空时，直接把标的区替换成一行说明「这本账户暂无可卖出持仓」+「去买入」快捷切换，不再渲染一个必然为空的输入框。

**② 「当天」勾选框与日期联动（消掉 P2/P3）**

- 日期 = 今天 → 勾选框显示，文案改白话：
  - 买入：`计入当日盈亏（按买入价算）`
  - 卖出：`卖的是今天买的（按买入价算盈亏）`，默认勾选不变；
- 日期 ≠ 今天 → **勾选框整行收起**，原位置换成一行灰字说明：`补录记录不参与当日盈亏统计`（与后端口径 AccountService.java:542 完全对齐，前端不再提交无效的 `today` 字段）；
- 勾选框旁加 `?` 气泡（全站统一的 `.hint-q` 形态，system.html:78 是样板），一句话解释基准价规则，不出现任何开发词。

**③ 成交额实时反馈 + 现金上限前置（消掉 P4）**

- 数量、成交价任一变化 → 实时算 `成交额 = 数量 × 价格`，显示在按钮上方一行：
  - 买入：`成交额 ¥12,340.00 · 保存后可用余额 ¥87,660.00`；余额不足时**保存按钮置灰** + 红字提示（不再等后端报错）；
  - 卖出：`成交额 ¥12,340.00 · 卖出后可用余额 ¥112,340.00`。
- 买入数量输入框加 `max`（= floor(可用现金 / 当前价格)），与卖出侧现有的 max 口径对称（account.html:944-945）。

**④ 成交价必填前置 + 预填反馈（消掉 P5）**

- 「成交价」标必填星号；买入时价格为空 → 保存按钮置灰 + 提示「买入需填写成交价」（与 AccountService.java:595 前置一致）；
- 预填行情价时输入框显示 loading 态（转圈或骨架），失败时给一行灰字「未取到行情价，请手动填写」，不再静默。

**⑤ 买入补持仓上下文（消掉 P6）**

- 选中的标的已有持仓时，note 行显示：`已持有 1,200 股 · 成本价 ¥1,510.00 · 加仓后成本约 ¥1,512.30`（加权公式与 AccountService.java:638-641 一致，纯前端预估）；
- 与卖出侧的「可用 N 股」共用同一个 note 位置（account.html:936-953），视觉对称。

### 2.2 P1 — 选择器通用增强（stock-picker.js，全站受益）

**⑥ 空候选首轮给「最近持仓/热门标的」**：聚焦无关键字时不再只显示提示文案（stock-picker.js:351-355），改为展示候选——账户页用持仓清单，其它页面用名录前几条；仍然不发无谓请求（候选来自调用方的 `source` 或页面传入的一小撮）。

**⑦ 手输回车有明确反馈**：DB 模式敲了纯数字代码回车但名录无匹配时，给出明确提示「名录中没有 XXX，请从列表选择」（替代现在的无声失败，stock-picker.js:432-434）；「可直接输入完整代码后回车」的提示语改为按实际能力渲染，不误导。

**⑧ 粘贴「名称(代码)」容错**：从别处复制 `贵州茅台(600519)` 粘进输入框时，自动剥出 6 位代码匹配（正则提取括号内/末尾 6 位数字重搜），命中即高亮候选。

### 2.3 P2 — 视觉与细节

**⑨ 弹窗分区**：`交易方向（方向段 + 标的）｜交易明细（数量 + 成交价 + 成交额反馈行）｜记录归属（日期 + 当天口径）` 三段，段间细分隔线；保存按钮 loading 态（沿用 `.btn` disabled 样式，account.html:1003-1004 已有禁用逻辑，补视觉）。
**⑩ 保存成功后仅刷新受影响区块**（持仓卡 + 记录列表），不整页 `enterAccount` 重载（account.html:1023），减少弹窗关闭后的闪动。

## 3. 「是否当天」字段还落库吗？——结论：**还落库，保持现口径**

**当前树的数据流（v1.6.2 实测）：**

```
前端勾选 today (account.html:1012)
  → AccountService.addRecord(:536)
      onToday  = today.equals(date)                    // :543 成交日是否今天
      sameDay  = (todayFlag==null || todayFlag) && onToday   // :545 意图 ∧ 当天
  → TradeRecord.sameDay 落盘 (:707)
      FileAccountRepository.java:646（JSON）/ DbAccountRepository.java:343（MySQL）
      导入导出同样带该字段 AccountTransferService.java:118/359
  → 展示：前端直接读 x.sameDay 画「当天」tag（account.html:834）
```

**三种选择的分析：**

| 方案 | 说明 | 判定 |
|---|---|---|
| A. 保持现状（sameDay 落库） | 存的就是「意图∧当天」的**最终生效值**；`realizedProfit` 有值时，这个 tag 是唯一能解释「这笔当日已实现按当日买入均价还是昨收算的」（AccountService.java:660-665）的线索 | ✅ **推荐** |
| B. 改存原始意图 `todayFlag`，展示时读时重算 | 信息量等价（`sameDay = todayFlag && tradeDate == time[0:10]`，`time`:710 首段即录入日），只是把合取从写时挪到读时——**一个 boolean 换一个 boolean，没有存储收益**，却要动两套仓储 + 导入导出 + DB 模式迁移 | ❌ 收益薄 |
| C. 两个字段都不存 | **信息丢失**：无法区分「今天成交但没勾当天」（卖出按昨收算）与「补录」——历史记录的盈亏基准变成悬案 | ⛔ 不可 |

**结论**：`sameDay` 落的是**录入时的会计口径快照**，不是可推导的冗余字段——它回答的是「这笔已实现盈亏当时按什么基准算的」，属于操作记录作为历史凭证的一部分。需要修的只是展示层两件事（即 2.1-②）：

1. 补录场景前端不再提交无效勾选、并解释「为什么没有当天 tag」（现在用户勾了却看不到，以为是 bug）；
2. 「当天」tag 加 title 说明（`当日口径：基准价为当日买入均价`），把字段含义从开发视角挪到用户可懂的话。

> 附注：项目记忆中 v1.6.3 曾有「读时重算（viewOf）」的口径，当前 v1.6.2 树内不存在该实现（`grep viewOf` 为空、无 v1.6.3 提交）；本方案按当前树为准，若后续合入 v1.6.3 改动，2.1-② 的结论不变（写时合入 `onToday` 的口径与读时重算等价）。

## 5. 验收标准

1. **三段式 Playwright**（v1.6.3 样板，`NODE_PATH` 跑法见 MEMORY）：
   - 功能段：弹窗字段顺序断言、切方向保留已选（选中持仓标的 → 切卖出 → 断言仍在）、补录日期断言勾选框隐藏 + 提示出现、成交额行随输入实时变化、余额不足保存置灰、买入空价格保存置灰；
   - 重启段：落盘 JSON 写→停→起二轮，`sameDay` 字段与 tag 展示不回退（落盘铁律）；
   - 样式段：亮暗双主题 `getComputedStyle` 逐项断言（新增反馈行/必填星号/分区线两主题都验）。
2. **选择器回归**：盯盘页 / 回测页 / 更新页各跑一轮冒烟（2.2 的 picker 改动是全站的），确认下拉定位、手输兜底无回归。
3. **口径断言**：补录一笔（日期选昨天）→ 记录无「当天」tag、当日已实现不计入；当天勾选一笔 → tag 出现且当日盈亏变动——与后端 `AccountService.addRecord` 日志断言一致。
4. 文案黑名单扫描：新文案无「落库/口径/标记/基准价」类开发词（2.1-② 的白话文案过 `DEV_WORDS`/模式扫描）。
