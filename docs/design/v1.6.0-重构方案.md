> 依据 `docs/design/releasev1.6.0.md`。本方案把「改名 + 拆模块 + 提示文案收敛」拆成可独立验收的阶段，
> 每阶段跑通构建与自测再进下一阶段。

## 0. 已确认的口径（2026-09-20）

| 项 | 结论 |
|---|---|
| 域名口径 | GitHub 账号 `zhoutaoq` → groupId `io.github.zhoutaoq` |
| 模块划分 | `shadow-flow-parent`（聚合） / `shadow-flow-notify`（通知 SDK） / `shadow-flow-biz`（Web 服务） |

## 3. notify SDK 的边界（硬约束）

**进 SDK（通用能力，与业务无关）**

- 消息模型：`NotifyMessage{ channel, target, title, content, contentType(TEXT|MARKDOWN), keywordTag, meta }`
- 通道 SPI：`Notifier{ String channel(); NotifyResult send(NotifyMessage) }`
- 目标解析 SPI：`NotifyTargetResolver{ String resolve(String channel, String targetKey) }`（biz 用系统级配置行实现）
- 门面：`NotifyService.send(NotifyMessage)` —— 串起 开关 → 时段闸门 → 限流 → 通道发送
- 通道实现：钉钉群机器人 webhook（HTTP + JSON 转义 + 超时），**不含任何业务词**
- 通用支撑：公网 IP 探测、JSON 文本转义、HTTP POST
- 策略：允许发送时段（通用"静默时段"语义）、同内容限流

**不进 SDK（留在 biz）**

- 任何业务文案：`[智能盯盘-IP]`、`【生产发布】`、`[关键词] 新用户注册`、`[关键词] 用户反馈`、告警正文
- 任何业务概念：股票、盯盘、注册、反馈、阈值、交易时段口径
- 任何 Spring Web / Controller / 仓储 / 页面资源

**判据**：把 notify 的 jar 单独给另一个项目用，不改一行代码、不加任何业务配置就能跑通 —— 做不到说明边界破了。

> 现状问题（本次要修的）：`DingTalkNotifier.keywordTag()` 里写死 `[智能盯盘]`，`send()` 直接绑定盯盘语义，
> 且依赖 `WatchProperties`。抽 SDK 时前缀改由 biz 通过 `NotifyMessage.keywordTag` 传入。

## 4. 配置键改名与迁移

`waizao.*` 是本项目自己的配置根（不是外部站点名，外部地址常量在 `waizao.api.base-url` 里），改为 `shadowflow.*`：

| 旧 | 新 |
|---|---|
| `waizao.db.enabled` | `shadowflow.db.enabled` |
| `waizao.store.*` | `shadowflow.store.*` |
| `waizao.account.*` | `shadowflow.account.*` |
| `waizao.auth.notify.*` | `shadowflow.auth.notify.*` |
| `waizao.api.*` | `shadowflow.api.*`（`base-url` 的值 `http://api.waizaowang.com` **不改**） |
| `waizao.max-span-days` / `waizao.stock-list-file` | `shadowflow.max-span-days` / `shadowflow.stock-list-file` |
| `watch.*` / `app.*` / `feedback.*` | 保持不变（不在本次范围） |

**存储层同步改**（用户已确认一并改）：

| 旧 | 新 | 迁移 |
|---|---|---|
| 表 `waizao_*`（共 11 张） | `shadowflow_*` | 启动时探测旧表存在则 `RENAME TABLE`（幂等） |
| 系统级配置行场景键 `waizao` / 通道键 `dingtalk` | `shadowflow` / 保持不变 | 启动时把旧场景键行改写成新键 |
| `data/` 目录 | `data/` **不变** | 目录名不含品牌，不改动（避免线上一堆绝对路径失效） |
| `sys-config.json` / `watch-config.json` | 文件名不变 | 只改里面的场景键值 |

> 迁移写成幂等启动钩子（`ShadowFlowDataMigration`），只在检测到旧结构时执行一次，跑完打日志留痕。
> 生产 data 目录有 4 个用户的盯盘配置与账户数据，迁移前**先在服务器上备份 `data/` 与 `sys-config.json`**。

## 5. 提示文案收敛（`?` 气泡）

规范：**系统内保证文案应无尽无**；必须给的说明收进 `?`，默认不展开。

- 组件：`common.css` 里做 `.hint-q`（一个 `?` 圆形小标）+ `.hint-box`（气泡），纯 CSS 展开：
  `:hover` / `:focus-visible` / `:focus-within` 显示；移动端靠 `tabindex="0"` 点按获得焦点显示，再点收起。
- 首批落地点：`pages/system.html`（第三方对接、股票名称跳转、首页背景行情三块的长说明）、
  `pages/watch.html`（推送卡说明）、`pages/account.html`（若有长说明）。
- 验收：默认态页面上不出现成段说明文字；`?` 可键盘聚焦、可点按展开、气泡不被容器裁切。

## 8. 风险

| 风险 | 应对 |
|---|---|
| 141 个文件改包名，漏改 import | 用 `git mv` 改目录 + 全量替换 `package/import` 行，再靠编译兜底（编译不过就是漏了） |
| notify 抽得过宽又变成业务耦合 | 用第 3 节判据自检；SDK 内 grep 不到任何业务词 |
| 配置键改名导致线上起不来 | 迁移钩子幂等 + 保留旧键兜底读取（读不到新键时回读旧键并警告） |
| 前端长文案收进气泡后信息缺失 | 关键限制（如「留空 = 用平台默认群」）保留在标签或 placeholder，不塞进气泡 |
