# 回测策略扩展清单

> 目的：盘点当前回测引擎已实现的买卖策略能力边界，参考开源框架与主流量化回测平台的常见策略库，整理出**可落地实现**的买入/卖出策略清单，用于优化回测效果、扩大策略覆盖范围。
>
> 定位：这是**规划文档**（清单 + 落点），不是实现文档。每一项都标注了「改动落点」，方便后续按优先级挑选实现。

---

## 一、当前已实现策略盘点

### 1.1 判断组件（`BacktestCondition` 的 4 种 TYPE）

| TYPE 常量 | 中文名 | 语义 | 使用字段 |
|---|---|---|---|
| `CHANGE` | 涨跌幅 | 近 N 个交易日涨幅 大于/小于 X%（X 可为负） | `close` |
| `ABOVE_MA_DAYS` | 站均线 | 连续 N 个交易日收盘价 大于/小于 M 日线 | `close` + MA |
| `CLOSE_MA` | 收盘价 | 当日收盘价 大于/小于 N 日线 | `close` + MA |
| `VOLUME_MA` | 量能比 | 当日成交量 大于/小于 前 N 日平均成交量 × ratio | `volume` |

**组合方式**：一个策略组（`BacktestRule`）= 一个 `logic`（`and` / `or`）+ 一串 condition。买入、卖出各一个策略组，两组之间无依赖关系。

**引擎能力边界**（这就是"还能加什么"的物理上限）：

| 维度 | 现状 | 缺口 |
|---|---|---|
| 数据字段 | 仅 `open / close / high / low / volume / amount / preClose` | **无换手率、无流通市值、无财务数据、无行业分类** |
| 组合逻辑 | 单层 `and` / `or` | 无嵌套分组、无优先级、无条件间先后依赖 |
| 仓位管理 | 全仓买入 / 全仓卖出 | 无分仓、无加仓、无金字塔 |
| 卖出机制 | 与买入同一套 condition（信号驱动） | **无固定止损 / 止盈 / 跟踪止损 / 时间止损** |
| 信号成交 | T 日收盘确认 → T 日收盘价成交（A 股 T+1 用 `Pending` 顺延） | 无盘中触发价、无信号确认过滤器 |
| 涨跌停 | `LimitConfig` 三策略（忽略 / 次日开盘 / 次日开盘+阈值） | 已较完整，可不动 |

### 1.2 结论：可扩展的三个层次

所有新增策略，无非落在以下三级中的一个或多个：

```
① 模型层  BacktestCondition  →  加 TYPE 常量 + validate() 分支
② 引擎层  BacktestService    →  match() switch 加 case + Indicator 加指标计算
③ 前端层  backtest.html     →  chips 数组 + condRow() 参数行 + buildRule() 字段组装
```

**只要新策略是"用 OHLCV 算出来的日频布尔判断"，就一定能用这套模板落地，无需改数据结构。**
反之，涉及换手率/市值/财务的策略，需要先补数据源（见第五节）。

## 二、买入策略清单

### A. 趋势跟随类（存量能力可直接覆盖，优先级最高）

| # | 策略 | 语义 | 落点 | 复用性 |
|---|---|---|---|---|
| A1 | **均线金叉** | MA(短) 上穿 MA(长) | 新增 TYPE `MA_CROSS`，`match()` 比较 `ma(i,short)` 与 `ma(i,long)` 且 `ma(i-1,short) <= ma(i-1,long)` | 高，`Indicator.ma()` 已就绪 |
| A2 | **均线多头排列** | MA5 > MA10 > MA20 > MA60 | 新增 TYPE `MA_ALIGN`，参数 `m` 存逗号串或用 3 个字段 | 高 |
| A3 | **均线支撑回踩** | 价跌破 MA(N) 后 N 日内重新站上 | 可由 `ABOVE_MA_DAYS`(n=1) 近似 | **零改动**，用现有组件拼 |
| A4 | **多头趋势确认** | 收盘价 > MA20 且 MA20 斜率 > 0 | 新增 TYPE `MA_SLOPE`（MA 斜率），或 `CLOSE_MA` + `CHANGE` 组合近似 | 中 |

> **A3 是零改动项**：现有 `CLOSE_MA`（收>MA20）+ `CHANGE`（近5日涨幅>0）用 `and` 拼起来，就已经是一个可用的趋势确认策略。文档里列出它是为了说明"组合能覆盖一部分需求，不必急着加 TYPE"。

### B. 突破类

| # | 策略 | 语义 | 落点 |
|---|---|---|---|
| B1 | **N 日新高突破** | 收盘价 > 前 N 日最高价 | 新增 TYPE `BREAK_HIGH`，需 `Indicator.maxHigh(i,n)` |
| B2 | **唐奇安通道**（海龟） | 收盘价 > 前 N 日高点（上轨） | 同 B1，`Indicator` 加 `donchianUpper(i,n)` |
| B3 | **箱体突破** | 价格突破近 N 日区间上沿 × (1+缓冲) | 同 B1，加 `buffer` 参数 |
| B4 | **放量突破** | 突破 + 量能确认 | **零改动**：B1 + `VOLUME_MA` 用 `and` 组合 |

> **当前引擎最大缺口就是 B 类**：`high` 字段已经在 `StockKlineDaily` 里了，但 `Indicator` 完全没有基于 `high/low` 的计算方法。**B1 是性价比最高的一项新增** —— 一个 `maxHigh(i,n)` 方法就能解锁整个突破策略族。

### C. 摆动 / 超跌反转类

| # | 策略 | 语义 | 落点 | 阻碍 |
|---|---|---|---|---|
| C1 | **RSI 超卖** | RSI(14) < 30 后回升 | 新增 TYPE `RSI`，`Indicator.rsi(i,n)` 需维护涨跌均值序列 | 中，需新增滚动状态 |
| C2 | **KDJ 金叉** | K 上穿 D，且 D < 20 | 新增 TYPE `KDJ`，需最高/最低价窗口 | 中，指标计算稍重 |
| C3 | **BIAS 乖离** | 收盘价偏离 MA(N) 超过 -X% | **新增 TYPE `BIAS` 或直接复用 `CLOSE_MA`** —— BIAS = (close - ma)/ma，本质就是"收盘价与均线"的相对距离 | **低，可零改动近似** |
| C4 | **MACD 金叉** | DIF 上穿 DEA | 新增 TYPE `MACD`，需 12/26/9 EMA 三组状态 | 中高，需维护 EMA 序列 |
| C5 | **威廉指标 WR** | WR(14) < -80 | 新增 TYPE `WR`，与 KDJ 共用高低价窗口 | 中 |

> **C3 提示**：`CLOSE_MA` 现在的语义是"收盘价 > 或 < N 日线"，如果引入 BIAS 的百分比语义，其实是同一个物理量的两种表达。实现时可考虑给 `CLOSE_MA` 加一个"按百分比"的开关，而不是新增 TYPE —— 这样前端只多一个 chip，后端只多一个 if 分支。

### D. 量价关系类

| # | 策略 | 语义 | 落点 |
|---|---|---|---|
| D1 | **放量上涨** | 涨幅 > X% 且 量 > 前 N 日均量 × R | **零改动**：`CHANGE` + `VOLUME_MA` 用 `and` |
| D2 | **缩量回踩** | 收盘价 > MA20 且 量 < 前 N 日均量 × R | **零改动**：`CLOSE_MA` + `VOLUME_MA`（`op=lt`）用 `and` |
| D3 | **地量见底** | 量 < 前 N 日均量 × 0.5 | **零改动**：`VOLUME_MA`（`op=lt`, `ratio=0.5`） |
| D4 | **量价齐升** | 连续 N 日量增价涨 | 新增 TYPE `VOL_PRICE_UP`，或 `CHANGE`+`VOLUME_MA` 近似 |
| D5 | **换手率放大** | 换手率 > X% | ⚠️ **需补数据**，见第五节 |

> D 类是**现有引擎覆盖最好的区域**。D1/D2/D3 完全不用写代码，前端点几下就能配出来。这也说明：**推出策略库（预置模板）比新增指标更能立刻提升可用性**。

### E. 波动率 / 通道类

| # | 策略 | 语义 | 落点 |
|---|---|---|---|
| E1 | **布林带突破上轨** | 收盘价 > MA(N) + K×STD(N) | 新增 TYPE `BOLL_BREAK`，`Indicator.std(i,n)` |
| E2 | **布林带收口后突破** | 带宽收窄到历史低位后向上突破 | 新增 TYPE `BOLL_SQUEEZE`，需带宽历史序列 |
| E3 | **ATR 过滤** | ATR(N) / close < 阈值（低波动）才开仓 | 新增 TYPE `ATR_FILTER`，`Indicator.atr(i,n)` 需要真实波幅 |
| E4 | **振幅过滤** | (high-low)/preClose > X% | 新增 TYPE `AMPLITUDE`，字段现成（`high/low/preClose`） |

### F. 形态 / 时间类

| # | 策略 | 语义 | 落点 |
|---|---|---|---|
| F1 | **连续下跌后企稳** | 连跌 N 日后首次收阳 | 新增 TYPE `REVERSAL`，或 `CHANGE`（x 为负）+ `CHANGE`（近1日 x>0）近似 |
| F2 | **周线/月线确认** | 周线金叉 | ⚠️ 需做周期聚合，建议在指标层做 `ma(i*k, n)` 的倍数取数 |
| F3 | **特定月份/季节** | 只在某月买入 | 新增 TYPE `CALENDAR`，`TradeCalendar` 已有日期 |
| F4 | **涨停板次日** | 昨日涨停今日买入 | 新增 TYPE `LIMIT_UP_YESTERDAY`，用 `preClose` 判断 |

## 三、卖出策略清单

卖出分两大族：**信号驱动卖出**（与买入同构，直接复用上面的 TYPE）与**风控驱动卖出**（当前引擎完全缺失，是最大缺口）。

### 3.1 信号驱动（镜像买入，零新增能力）

| # | 策略 | 配置方式 |
|---|---|---|
| S1 | **均线死叉** | 镜像 A1，`MA_CROSS` + `op=lt` |
| S2 | **跌破均线** | 现有 `CLOSE_MA` + `op=lt` |
| S3 | **连续 N 日跌破均线** | 现有 `ABOVE_MA_DAYS` + `op=lt` |
| S4 | **冲高回落** | 现有 `CHANGE` + `op=lt` |
| S5 | **放量滞涨** | `CHANGE`(lt) + `VOLUME_MA`(gt) 用 `and` |
| S6 | **N 日新低** | 镜像 B1，`BREAK_LOW` |

> 卖出侧的信号类策略，**只要买入侧新增了 TYPE，卖出侧自动可用**（同一套 `match()`）。所以新增指标的收益是双份的。

### 3.2 风控驱动（🔴 当前完全缺失，强烈建议优先补）

| # | 策略 | 语义 | 落点 |
|---|---|---|---|
| **R1** | **固定止损** | 浮亏超过 X% 立即卖出 | 🔴 需在引擎循环里记录**持仓成本**，新增独立卖出检查（不走 condition） |
| **R2** | **固定止盈** | 浮盈超过 X% 卖出 | 🔴 同 R1 |
| **R3** | **跟踪止损**（移动止盈） | 从最高点回撤 X% 卖出 | 🔴 需维护**持仓期最高价** `peakPrice` |
| **R4** | **时间止损** | 持仓超过 N 个交易日未获利则卖出 | 🔴 需维护**持仓天数** `holdDays` |
| **R5** | **保本止损** | 浮盈达 X% 后，回落到成本价卖出 | 🔴 R1 + R2 的组合状态机 |
| **R6** | **ATR 止损** | 买入价 - N×ATR 作为止损线 | 🔴 R1 的动态版本，需 `Indicator.atr()` |
| **R7** | **移动均线止盈** | 跌破 MA(N) 卖出 | ✅ **已有**：`CLOSE_MA` + `op=lt`（近似） |
| **R8** | **最大回撤止损** | 总资产从峰值回撤 X% 停止交易 | 🔴 账户级，需在循环里跟踪 `peakTotalAmount` |

**R 类的架构影响（重要）**：

现在引擎的结构是"`match(condition)` → 决定买/卖"，纯**无状态信号判断**。而 R1-R6 都是**有状态**的：

```
买入时   记录：持仓成本 costPrice、持仓日 buyIndex、持仓期最高价 peakPrice
每日      计算：浮盈浮亏率 = (close - costPrice) / costPrice
卖出判断  优先级：风控条件（止损/止盈）> 信号条件（condition）
```

建议的落地方式：在 `BacktestService` 的逐日循环里，**卖出判断前先跑一遍风控检查**，风控命中就直接置为卖出信号，不再看 `sellRule`。这需要：

1. `BacktestRunRequest` 新增 `RiskConfig`（止损/止盈/跟踪止损/时间止损的开关与阈值）
2. `BacktestService` 新增持仓状态（`costPrice` / `peakPrice` / `holdDays`）
3. 卖出优先级：`风控 > sellRule`
4. 前端新增「风控设置」区块（与现有「涨跌停成交」并列）

> **这是本次整理中唯一需要动引擎主循环的改动**，其余所有项都只是在 `match()` 里加 case。建议单独立一个需求做。

## 四、组合与仓位增强（进阶）

| # | 能力 | 说明 | 影响 |
|---|---|---|---|
| P1 | **分批建仓** | 首次买 50%，回踩再买 50% | 改账户模型，`Pending` 与仓位计算全改 |
| P2 | **金字塔加仓** | 每涨 X% 加仓一份 | 同上 |
| P3 | **固定金额/股数** | 每次买固定金额，而非全仓 | 中等，改 `run()` 的下单量计算 |
| P4 | **策略组嵌套** | `(A and B) or (C and D)` | 改 `BacktestRule` 结构为树，前端改动大 |
| P5 | **买入冷却期** | 卖出后 N 日内不再买入 | 低，加一个 `lastSellIndex` 判断 |
| P6 | **最大持仓数** | 同时最多持有 N 只（需多标的回测） | 需多标的数据结构，改动大 |

> P1-P2 属于仓位管理，会打破"全仓"这个当前核心假设（`run()` 里大量逻辑依赖"全仓买入/全仓卖出"）。**不建议在策略扩展阶段做**，可作为独立的"账户模型重构"需求。

## 五、需要补充数据源的策略（暂不实现，标注清楚）

以下策略**不能**用现有字段算出来，实现前必须先补数据：

| 数据项 | 需要的策略 | 补齐方式 |
|---|---|---|
| **换手率** | D5 换手率放大、流动性过滤 | `volume / 流通股本`，需补流通股本数据 |
| **流通市值 / 总市值** | 小市值轮动、市值过滤 | 需补市值快照 |
| **行业 / 板块分类** | 板块轮动、行业内选股 | 需补行业分类表 |
| **财务数据**（PE/PB/ROE） | 基本面选股、价值策略 | 需接财务数据源，工作量大 |
| **北向资金 / 龙虎榜** | 资金流策略 | 需接外部数据源 |
| **复权因子** | 精确的长期回测 | ⚠️ 需确认现有 K 线是否前复权（若已复权则可忽略） |

> **建议**：这些先只做"标注"，不排期。项目当前是**单标的、日频、纯技术面**回测，技术面策略族（A-F）已经足够覆盖绝大多数需求。

## 六、实现优先级建议

按 **"收益/成本"** 排序，给出三档：

### 🥇 第一档：零代码 / 极低成本，立刻提升可用性

| 项 | 做法 | 成本 |
|---|---|---|
| **预置策略模板** | 前端加一组「常用策略」一键填充（放量突破、缩量回踩、均线趋势、超跌反弹…） | 纯前端，1 天 |
| **现有组件组合说明** | 文档 + 前端提示，告诉用户 `and`/`or` 能拼出哪些组合 | 0 |
| **`BREAK_HIGH` / `BREAK_LOW`** | `Indicator.maxHigh/minLow`，解锁整个突破族 | 后端小改 |

### 🥈 第二档：中等成本，覆盖主流量化策略

按实现顺序：

1. `MA_CROSS` 均线金叉/死叉（A1、S1）—— 最经典，用户最先找的就是它
2. `MACD`（C4）—— 平台必备
3. `RSI`（C1）+ `KDJ`（C2）—— 超买超卖族
4. `BOLL_BREAK`（E1）—— 布林带
5. `BIAS`（C3）—— 或给 `CLOSE_MA` 加百分比开关

### 🥉 第三档：需要动引擎，单独立项

- **风控卖出 R1-R6**（🔴 最值得做，当前完全没有止损能力，实盘意义重大）
- 仓位管理 P1-P3
- 策略组嵌套 P4

## 七、统一落点速查表

新增一个基于 OHLCV 的日频判断，标准三步：

**① 模型层 `src/main/java/com/stock/kline/model/BacktestCondition.java`**

```java
// 1) 加常量
public static final String TYPE_MACD = "MACD";

// 2) validate() 的合法类型白名单里加上它
if (!TYPE_CHANGE.equals(type) && ... && !TYPE_MACD.equals(type)) { ... }

// 3) 按需加参数校验（m / x / ratio / 新字段）
```

**② 引擎层 `src/main/java/com/stock/kline/service/BacktestService.java`**

```java
// match() 的 switch 里加 case
case BacktestCondition.TYPE_MACD: {
    // 调 Indicator 的新方法
    return ind.macdCross(i, c.getM(), gt);
}

// Indicator 内部类里加指标方法（按需加缓存字段，参考 maCache）
```

**③ 前端层 `src/main/resources/static/pages/backtest.html`**

```javascript
// 1) condRow() 的 types 数组加一项（含中文短标签 t + tooltip full）
{v: 'MACD', t: 'MACD', full: 'MACD 金叉/死叉'},

// 2) condRow() 里加参数行分支（if / else if）
} else if (c.type === 'MACD') {
    main = `... N 参数行 ...`;
}

// 3) buildRule() 里加字段组装
} else if (c.type === 'MACD') { o.n = Number(c.n); o.m = Number(c.m); }

// 4) 导入导出兼容（默认值数组加一条，避免老 JSON 缺字段）
```

**④ 别忘了**：`BacktestService.warmupDays()` 要能识别新 TYPE 的窗口长度（`n` / `m`），否则预热不足会算错指标。

## 附：一句话总结

> 当前引擎已经把「**用收盘价/成交量做日频布尔判断**」这条路修通了，剩下的工作 90% 是**往 `match()` 的 switch 里加 case**。
>
> 最该先做的是两件：**① 预置策略模板**（零代码就能让用户用上 A-F 类里的组合策略）；**② 风控卖出**（止损/止盈/跟踪止损，当前完全没有，是最大的能力缺口）。
